### B0 — UMAP is still nondeterministic *with* `random_state=42`; two identical builds of the default dataset give different hierarchies
**CONFIRMED** · `src/analysis/dim_reducer.py:100-103`, reached from `src/analysis/analysis_routine.py:115` · seeding claim is **[24h]** (`1d85891`), the `_umap` body is **[pre]** · **BLOCKER**

The window threaded `random_state` into `umap.UMAP`, but that does not make the embedding reproducible when the fuzzy kNN graph is **disconnected**: UMAP's default `init="spectral"` then falls into `umap/spectral.py::multi_component_layout`, which places components outside the seeded path. `_umap` passes no `init`, so the default is used. The default dataset — "Wine quality (Low)", 6497 rows — produces a disconnected graph, and the pre-clustering UMAP feeds HDBSCAN, so the *entire hierarchy* changes between identical runs.

```
$ PYTHONPATH=. .venv/bin/python review_repro/10_umap_still_nondeterministic.py
X: (6497, 11)   umap_random_state: 42   n_neighbors: 15

=== 1. three identical UMAP calls through the repo's own code path ===
  run0 vs run1: identical=False   max|diff|=15.7355   (coordinate scale 19.49)
  run0 vs run2: identical=False   max|diff|=18.0338   (coordinate scale 19.49)

=== 2. what that does to the clustering the hierarchy is built from ===
  run0: n_clusters=33   n_noise=624
  run1: n_clusters=61   n_noise=1226
  run2: n_clusters=69   n_noise=1207

=== 3. why: the fuzzy graph is disconnected at this size ===
  connected components in the fuzzy graph: 2

=== 4. the fix: a deterministic init ===
  init=spectral  identical=False   max|diff|=12.1757
  init=pca       identical=True    max|diff|=0.0000
  init=random    identical=True    max|diff|=0.0000
```

`max|diff|` of 18.0 against a coordinate scale of 19.5 is a different embedding, not float noise. The threshold matches the graph structure exactly: n=6000 → 1 component → identical; n=6300 → 2 components → not. Independently, a full `compute_analysis_tree` twice gave 60 vs 61 leaves with different partitions. Threading was ruled out (pinning `OMP`/`OPENBLAS`/`MKL`/`NUMBA` to 1 thread does not fix it) and so was kNN (indices and distances are bit-identical).

Consequences: every number the tool produces on wine is irreproducible; combined with §B3 (the cache has no code version) a cached tree can never be regenerated by rerunning; and §B1's remedy (thread the replicate seed through) will *not* by itself restore reproducibility here.

**Fix:** pass `init="pca"` in `_umap` (verified deterministic above), then assert determinism — build twice, compare — before freezing any number.

### B1 — Threading DR seeds silently collapsed every H1a replicate; the reported p-values are invalid
**CONFIRMED** · `src/analysis/dim_reducer.py:57,65` (cause) → `src_research/hierarchical_vs_flat.py:87,263,277,388` (victim) · **[24h]** (`1d85891`) · **BLOCKER**

The window made `fit_dimensionality_reducer` pass `config["umap_random_state"]` / `["tsne_random_state"]` — both hardcoded to `42` in `src/config_defaults.py:52,55` — into the UMAP and t-SNE constructors. `hierarchical_vs_flat.run_cell` (line 259) builds its config with `init_state()` and sets only `cfg["method"]` and `cfg["hierarchical_layers"]`; the `seed` parameter is written into the label dict at line 277 and **read nowhere else**. Its own docstring (lines 33-36) states the opposite of what the code now does:

> "`reduce_dimensionality` does not thread a seed into UMAP / t-SNE, so those embeddings are stochastic. […] the `SEEDS` loop functions as *replicates* that capture embedding variance — the unit of the paired H1a test is a (region × seed) pair."

All 5 replicates per cell are now byte-identical. `_paired_deltas` (line 388) pivots on `index=["seed","region"]`, so `scipy.stats.wilcoxon` receives `5R` "independent" paired deltas built from `R` distinct values each repeated 5×.

```

t-SNE   replicate 0 vs 1..4 identical: [True, True, True, True]   max|diff| = 0.000e+00
PCA     replicate 0 vs 1..4 identical: [True, True, True, True]   max|diff| = 0.000e+00

  R=  8 regions | honest n=  8 p=1.00000   ->  inflated n= 40 p=0.8928835
  R= 12 regions | honest n= 12 p=0.42383   ->  inflated n= 60 p=0.0508892
  R= 20 regions | honest n= 20 p=0.18935   ->  inflated n=100 p=0.0024730   (CROSSES 0.05)
```

The same mechanism degrades three further harnesses: `predicate_stability.py` (wine arm — 5 "tree-rebuild replicates" are one tree, and pass (b) becomes a uniform `1.000`), `pipeline_tuning.py` (the 10-baseline/5-validation select-vs-test protocol compares a constant against itself), and `planted_subspace_recovery.py`.

**Fix:** set `cfg["umap_random_state"] = cfg["tsne_random_state"] = cfg["mds_random_state"] = seed` per cell in each `run_cell`, or set them to `None` to restore the documented stochastic-replicate semantics — then regenerate every H1a/H2 table.

### B5 — PCA, the default method, is unseeded and nondeterministic on wide or small nodes
**CONFIRMED** · `src/analysis/dim_reducer.py:81` · **[pre]** · **BLOCKER**

`_pca` constructs `PCA(n_components=n_components, **kwargs)` with no `random_state`, and the caller passes none. sklearn's `svd_solver="auto"` selects the **randomized** solver for wide-or-small matrices, which draws from the process-global numpy RNG — never seeded anywhere (`grep -rn "np.random.seed" src backend` → no matches). The same 24h commit that seeded t-SNE, UMAP and MDS left PCA out, and `"method": "PCA"` is the default (`src/config_defaults.py:47`).

```
$ ... review_repro/06_pca_is_unseeded.py
  n=600   p=12    narrow -> covariance_eigh    identical across 3 runs: True    max|diff| = 0.000e+00
  n=400   p=3000  wide -> randomized           identical across 3 runs: False   max|diff| = 2.426e+01
  config keys containing 'random_state': ['tsne_random_state', 'umap_random_state', 'mds_random_state']
```

Affected shapes are exactly the ones the tool produces on image data: Olivetti's root is 400×4096; every MNIST/Fashion-MNIST sub-cluster below ~7840 points is 784-wide and takes the randomized path. Narrow datasets (wine 6497×11, MNIST root 70000×784) take `covariance_eigh` and are deterministic. Confirmed on real Olivetti: three runs give non-identical embeddings; on a degenerate spectrum the top-2 subspace is arbitrary. `explained_variance_ratio` (serialized as `embedding_original_variance`, and drawn by `PcaVarianceBar`) is irreproducible with it.

Together with §B0 this means **both** default-path reducers are nondeterministic: PCA on wide/small nodes, UMAP on any disconnected graph.

**Fix:** add a `pca_random_state` and forward it, or pin `svd_solver="covariance_eigh"`/`"full"` so no RNG is consulted.

### B6 — Two "characteristics" panels z-score against different populations; the same points get opposite signs
**CONFIRMED** · `backend/characteristics.py:63-66` vs `src/analysis/analysis_routine.py:96,168,207` · **[24h]** (`8b38085`) · **BLOCKER**

`compute_analysis_tree` fits **one** `StandardScaler` at the root and thereafter only row-masks it, so the tree's `rel_characteristics` feature z-scores are **whole-dataset** relative at every depth. Independently reproduced on wine (5 of 11 features flip sign), Swiss roll (0.5588 vs 0.9889) and Iris. The two agree exactly at depth 1, because there the parent *is* the root — which is why this is invisible on a one-layer demo and appears only at the depth the tool exists for.

The new module's docstring asserts the premise that fails: *"The tree stores one `rel_characteristics` frame per cluster, contrasting that cluster with its parent's space."* For feature columns the tree contrasts against the **root's** space.

Two further inconsistencies sit in the same chart:

- **`normalize=false` puts raw means on the z-score axis.** `compute_analysis_tree:94-99` skips the scaler entirely when `config["normalize"]` is false, so `rel_characteristics.z_mean` becomes a raw mean — while `CharacteristicsRequest` (`backend/app.py:78-83`) has no `config` field at all and always standardizes. **Fix:** pick one baseline for both paths (pass the root scaler into the endpoint, or refit per node in `_build_next`), thread `normalize` into `CharacteristicsRequest`, use `ddof=0` for extras, and correct the docstring.

### H3 — Stress is scale-dependent but is reported as if comparable across DR methods
**CONFIRMED as a methodology defect; REFUTED as an implementation bug** · severity **MEDIUM** (refuter downgrade) · `src/evaluation/neighbor_metrics.py:89` · **[pre]** in substance

`sqrt(Σ(d_orig − d_emb)² / Σd_orig²)` has no scale normalization, and t-SNE/UMAP emit coordinates on an arbitrary scale. Holding neighbourhood structure fixed on a real breast-cancer PCA node and rescaling the embedding by `a`:

| a | stress | trust | cont | mrre_f | mrre_m |
|---|---|---|---|---|---|
| 0.25 | 0.807494 | 0.881387 | 0.949551 | 0.867168 | 0.948567 |
| 1.00 | **0.287243** | 0.881387 | 0.949551 | 0.867168 | 0.948567 |
| 4.00 | 2.217931 | 0.881387 | 0.949551 | 0.867168 | 0.948567 |
| 10.00 | 6.981688 | 0.881387 | 0.949551 | 0.867168 | 0.948567 |

Stress moves 24×; the other four are bit-identical. On the real cached wine roots, applying Kruskal's optimal isotropic rescale `a* = Σ(d_o·d_e)/Σd_e²`: PCA `0.3750 → 0.2776` (a*=1.356), UMAP `1.4476 → 0.3642` (a*=0.399). **Reported gap 3.86×; true gap 1.31×.** Every UMAP `a*` is ≈0.4, i.e. its coordinates are ~2.5× too large — and that magnitude is most of what the reported stress measures. `stress = 1.0` is exactly what an all-zero embedding scores (§B4), and the cache holds UMAP runs at 1.18–1.45, with 62–83 of ~70–126 QM9 nodes above 1.0 — reported as *worse than putting every point at the origin*.

At BASE the code already called ZADU's `{"id": "stress"}` and stored the same number; the window relocated the computation without changing its semantics. The defect is the *choice* of a scale-dependent metric for cross-method comparison when the same dependency ships `scale_normalized_stress` (spec id `sn_stress`), which is fully invariant — `0.224470` at every `a`.

**Fix:** report `sn_stress` instead of, or beside, raw stress; label the raw one scale-dependent if it stays.
